# 参考说明

## 能力模型

本 Skill 会将原始素材重组为更强的汇报叙事，重点围绕四个维度展开：

1. **结果**
   - 最终做成了什么
   - 哪个结果最值得被记住
   - 哪个变化最值得被汇报

2. **影响**
   - 为什么这个结果重要
   - 对业务、团队或组织产生了什么价值
   - 谁因此受益，或减少了什么损失

3. **复杂度**
   - 这个问题为什么难
   - 是否存在目标冲突、信息不充分、资源有限或跨团队协同难题
   - 是否需要做关键判断与取舍

4. **成长与杠杆**
   - 是否沉淀了可复用的方法、机制或模板
   - 是否创造了长期价值，而非一次性价值
   - 体现了什么更高层级能力

## 常见改写方式

### 1. 从动作改写为结果
弱表达：
- 协调多个团队推进项目。

强表达：
- 对齐多个团队的推进节奏和交付路径，推动原本卡住的关键里程碑恢复推进。

### 2. 从结果改写为影响
弱表达：
- 完成了上线方案。

强表达：
- 完成上线方案的同时降低了协同成本，并沉淀出可复用的后续推广模板。

### 3. 从参与改写为范围与 owner 角色
弱表达：
- 参与了项目规划。

强表达：
- 在目标尚不清晰的阶段主导跨团队规划，厘清职责边界，并把模糊需求转化为可执行方案。

### 4. 从执行改写为晋升叙事
弱表达：
- 成功交付了项目。

强表达：
- 在高协同复杂度和资源受限条件下，推动项目从模糊阶段走向稳定交付，同时兼顾短期结果和长期机制建设，形成超出单项目价值的组织收益。

## 输出类型选择建议

### 适合用“管理汇报版”的情况
- 面向老板或管理链路
- 需要快速扫读
- 关注当前进展、风险和下一步

### 适合用“项目总结版”的情况
- 需要沉淀一个项目的完整过程和结果
- 过程、结果和经验教训都重要

### 适合用“高管摘要版”的情况
- 需要极致压缩
- 阅读时间非常短
- 重点是帮助快速判断

### 适合用“晋升 / 自评版”的情况
- 用于绩效、校准、述职、晋升
- 需要强调职责范围、复杂度、影响力和成长
- 需要支撑更高一级能力判断

## 素材不够强时的追问建议

如果原始素材不足，可以补充追问：
- 最重要的可量化结果是什么？
- 这件事最难的地方是什么？
- 影响到了哪些团队、角色或链路？
- 有没有沉淀出机制、模板或方法论？
- 你最希望评审者记住哪一点？
