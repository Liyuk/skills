# 架构图设计参考

架构图用于回答具体问题，不是装饰。先确认读者和用途，再选择视角、粒度与形式。

## 选择视角

- 业务视图：表达用户/业务场景与支撑能力。
- 系统视图：表达系统边界、组件、数据归属和外部接口。
- 运行视图：表达关键请求/数据流、依赖、故障影响和恢复路径。
- 演进视图：表达现状、阶段变化和目标状态；只有状态有依据时才标注已稳定、建设中或计划替换。

一张图不要混合互相冲突的视角。分层和节点按真实系统选择，不强制使用业务层/中台层/基础层。

## 输出要求

图中节点、边、方向、边界和图例应能回答用户的架构问题。避免在未知时标出所有权、状态、性能或故障保障。对未知关系标明待确认，并在图外说明假设。仅在用户需要或能显著澄清关系时输出 Mermaid/PlantUML 代码。

如图表达阶段状态，可使用颜色或线型，并附文本图例；颜色只表示已有依据的状态，不默认绿色/黄色/红色含义。使用用户目标平台支持的语法，避免过度装饰。
