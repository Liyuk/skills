# 新环境入场：按情境选择下一步

归属：“缺方向、信息、授权还是支持”的拆分、先获取信息再汇报再要资源、价值链地图五类信息、导师三阶段与90天表、产品概览的判断模型写法，来自Liyuk公开文章。下面的分支表和模板字段是任务化整理，待真实使用校准。

## 按卡点选择入口

| 用户的说法 | 真正先处理什么 | 可交付 |
| --- | --- | --- |
| 只有需求，想证明自己 | 拆出现在的工作、价值判断者、已有信息与影响范围 | 缺口判断与一周信息获取计划 |
| 被交了一个大方向，没有起点 | 方向背后的指标、历史尝试、卡在哪个环节 | 访谈清单与地图空白 |
| 怕问基础问题露怯 | 准备开场和自学基础，想法讲成待验证 | 开场说法与先读材料 |
| 两位上级期待不同 | 识别工作条件冲突，准备一次目标与边界对齐 | 对齐要点，交one-on-one |
| 接手陌生系统或业务 | 从任务画链路，标未知 | 一页价值链地图 |
| 要带一位新人 | 结果、练习、支持、证据四项 | 90天节奏与回看点 |
| 要写入门概览 | 读者要作的判断 | 判断模型骨架与事实/推断/问题分栏 |

它不是工作日志，目的只是把零散信息变成可讨论的对象。

## 访谈准备

每位访谈对象写一行：为什么找他、想获得什么（目标、指标、历史尝试、当前卡点、资源归属）、我准备的背景与待验证思路、之后是否需要继续联系。访谈后记下分歧：不同背景的人对同一件事的判断差异本身就是信息。

只在材料确认某人提供连接、立场或决定时间投入时，才把他写进相应位置；不确定时写“待确认谁决定优先级”。

## 90天节奏

| 阶段 | 新人完成 | 带教者完成 | 共同产出 |
| --- | --- | --- | --- |
| 第1—30天：建立上下文 | 熟悉边界与协作方式，完成范围清晰的小任务，关键节点请求反馈 | 了解起点与目标，补关键上下文，安排低风险真实任务，介绍协作者，每周具体反馈 | 上手地图、一次任务复盘、下阶段目标 |
| 第31—60天：独立闭环 | 负责中等复杂度任务，参与方案讨论，完成一次协作交接 | 设计可控的拉伸任务，在方案和复盘节点校准，帮助获得资源但不替他推进 | 任务说明、可验证交付、一次取舍复盘 |
| 第61—90天：扩展判断 | 主动识别风险与依赖，比较路径，做一次分享或改进提议 | 逐步放权，连接更广协作网络，给阶段反馈 | 阶段总结、下阶段成长主题、一项可复用沉淀 |

带教者的边界：安全、合规或影响大的决定明确介入；信息不足时补上下文但保留新人组织判断的空间；可承受的错误帮助复盘，不急着替他修正一切；任务超出能力时调整范围与支持，不把压力包装成成长机会。

## 何时停止

用户下一周已经知道找谁、问什么、汇报什么时，停止扩展。方向选择要等信息补上；只要一份日程或概览时不强制做缺口诊断。
