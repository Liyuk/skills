# 关系边界：请求、背书与既有承诺

归属：长期互惠、帮助从对方问题出发、信息有边界、转介征求同意、拒绝不等于否定人，来自职业关系原文章。下面的请求分类和既有承诺处理为任务化候选；私人关系扩展尚待作者校准。

## 先拆对方要求的动作

| 请求 | 可以确认什么 | 不能混成什么 |
| --- | --- | --- |
| 分享信息 | 自己知道的事实、出处、时效和未知 | 可靠性未核验的保证 |
| 转发材料 | 接收者是否愿意、材料主人是否同意 | 对材料内容或能力的背书 |
| 介绍联系 | 双方是否有实际关联、是否愿意接触 | 隐形人情债或工作机会承诺 |
| 提供推荐 | 自己实际观察过的能力与合作范围 | 用未知表现替朋友争取结果 |
| 承担任务 | 可完成的范围、投入和期限 | 无限制可调用的个人资源 |

一个请求可能同时含几个动作。拆开后，用户可以只答应能可靠完成的部分，也可以拒绝全部；不需要用额外帮助交换拒绝权。

## 新请求与已经答应的事

新请求先核对意愿、能力、时间和权限，再决定答应、缩小、暂缓或拒绝。已经答应的事项不能按新请求处理：说明变化，核对对方已产生的依赖，尽早重新协商。没有明确影响时不编损失；不知道新时间就不要再给空承诺。

涉及推荐时，公开作品可支持“我看过这些作品”的有限描述；它不自动支持真实工作协作、可信度或业绩。实际观察到的事实可以分享，未观察到的能力保留未知。

## 第三方边界

介绍前确认材料主人同意分享必要内容，再确认接收者愿意接触。对方未回复不等于已经同意，也不应由此推断不愿帮忙的动机。联系方式、私聊和非公开评价不随请求自动获得分享许可。

如果已经获得明确同意，按相关性最小化信息，写清为什么双方可能有关联和自己了解到哪里。没有接收者承诺，不能对求助者保证回复、机会或结果。

## 尊重拒绝和关系延续

拒绝针对当前请求，可以说明有限理由，不必提供完整私人日程或自证已耗尽。用户想保留联系时，可在真实进展出现后回访，不制造维护频率和永久回报规则。关系是否继续由用户选择，skill 不替其断交。

具体威胁、索取凭证或反复惩罚拒绝，需要先理解行为风险；普通内疚、误会或不同意见不自动证明操控。
