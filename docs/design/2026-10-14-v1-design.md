# Liyuk Skills v0.1 设计

本文件取代早期规划中将 Ask Liyuk 作为全部个人判断容器的定位。用户授权本轮依次完成设计分析、方案、第一版实现及公开远端创建。

## 目标与架构

整个仓库蒸馏个人方法，Ask Liyuk 做统一入口。保留任务技能的独立可用性与现有证据边界。第一版面向日常自用，公开供试用；不宣称已实现完整的个人判断模拟。

发布八项技能：ask-liyuk、tech-planning、tech-review、metric-decision、management-retro、eng-reporting、experience-review、distill-experience。Ask 与蒸馏工具仅由用户主动调用，其余允许任务匹配时发现。五项工程技能从本人 MIT 仓库迁入，保留许可、来源、39 个历史评测案例；修复包外引用。

experience-review 从公开成长自查文章提炼：检查背景、问题、选择、判断、行动、结果、证据及个人贡献。不提供通用评分或虚构经历。Interview Book 的未稳定规划只用于设计参考，不复制未发布题目或第三方材料。

distill-experience 引导本人或其他作者还原一个真实经历，区分事实、事后解释和候选方法，生成待本人确认的方法卡。不自动写入成熟技能，不推断人格或声称获得本人背书。

## 文件边界

skills/<name> 自包含 SKILL.md、必要 references、LICENSE、agents/openai.yaml。catalog/skills.json 维护公开技能路径、调用方式、来源 ID 和验证状态。catalog/sources.json 登记固定来源 commit、文件哈希及来源工作区修改状态；公开方法说明保留出处。需要的共享工程合同复制至包内，并通过哈希校验防止偏移。

README 为任务目录与使用入口；docs/research 保存 Matt 分析，docs/design 保存当前设计；旧规划明确标为历史草案。evals 维护案例与验证记录。脚本不发送用户材料、不调用付费模型、不改安装环境。

## 分发与工具

支持直接复制单项技能目录。提供与 Matt 相同形状的 Claude 插件清单和 marketplace，但未实际验证的平台只记录静态校验结果。通用安装器是可选路径，不宣称已验证远端安装。

Python 3.10+ 与 PyYAML 6.x 用于校验。validate(root: Path) -> list[str] 检查真实 YAML、目录名称、引用、包外依赖、许可、来源 ID、路由清单、元数据、案例 ID、插件版本和技能清单。配置错误返回诊断，不在原地修复文件。

## 验证与公开

对校验器先编写会失败的负例，再实现。迁入案例仅称历史案例；新增案例的 expected_output 是检查标准，不是运行结果。第一版进行干净包复制、结构检查、脚本样例运行和独立行为冒烟，记录具体模型／范围与失败，不声称已在所有宿主运行。

远端创建为公开 Liyuk/skills。仅发布本人材料、保留许可的迁入技能、合成案例与必要来源说明。模型输出不冒充作者观点，评测材料不包含私有公司事实和用户档案。

## 后续

优先由本人校准经历审查和蒸馏工具，再从新任务观察中扩展检索评估、插件边界等专项技能。新能力先验证方法，后加入目录。
